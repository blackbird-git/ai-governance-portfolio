AI application security

AI Security Engineering Lab

A small test application built to answer one question: what stops an AI assistant from accessing information it shouldn't?

The problem

Picture an AI assistant helping someone look up financial records. Even if it has been instructed to respect privacy, a user might ask it to show somebody else's account or try to trick it into calling a restricted tool. Telling the model to behave isn't enough. The software around it must enforce the rules.

What I built

Created a local application with Python, FastAPI, and Ollama, using invented financial records rather than real customer data. It includes rules defining which requests and data are permitted.

Then I deliberately tested those boundaries. Some requests were legitimate; others tried to retrieve unrelated records, trigger unauthorized tool actions, or manipulate the application through prompt injection. The tests checked whether the application allowed or rejected the request, regardless of what the language model said.

I also connected security events to Wazuh, so attempts and failures could be inspected in a monitoring system instead of disappearing into a chat transcript.

What the tests showed

The controlled tests demonstrate how access checks can be enforced outside the model and how the resulting activity can be recorded. The code, test cases, observed behavior, and limitations are documented in the repository.

This is an independent lab using synthetic data. It is not evidence that a particular production AI system has been secured.
