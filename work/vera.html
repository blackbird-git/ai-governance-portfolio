Vera: Local AI Memory Engine

I built Vera as an offline family memory prototype. It became a way to test whether a local AI system could retrieve source records, track corrections, and avoid presenting unsupported details as facts.

Background

An AI model can generate a confident answer from partially relevant evidence, confuse two sources, or quietly turn an unsupported statement into a stored “memory.” I wanted to explore how a local application could preserve attribution and corrections while keeping the source records authoritative.

Approach

Attributed records

Store text records in local SQLite with source metadata, full-text search, and correction history.

Grounded retrieval

Retrieve and select evidence before asking a local model to compose a response, then validate references.

Controlled writes

Require explicit confirmation before a model-proposed memory becomes part of the archive.

Honest evaluation

Compare models and response strategies using synthetic datasets, holdouts, regression tests, and documented quality limitations.

My contribution: I defined the product and security boundaries, directed AI coding agents using acceptance criteria, designed evaluation questions and holdouts, reviewed results, and decided which experimental approaches should remain outside the reference engine.

Results and evidence

The public repository records 122 automated regression tests. Vera uses local SQLite storage and Ollama inference. The evaluation results are based on controlled synthetic datasets.

Model comparisons exposed a recurring tradeoff: more natural answers sometimes added details unsupported by the source. A planning experiment improved compliance with topic exclusions without improving answer completeness. Those failures informed decisions about what not to promote into the main engine.

Evaluation numbers are based on small synthetic datasets, with some agent-reviewed judgments. They are useful within the experiment but should not be treated as general-purpose model benchmarks.

Limitations

  • Conversational recall and answer completeness remain inconsistent.
  • The local archive is not encrypted, and there is no multi-user authorization layer.
  • The system does not process audio or images, despite the longer-term family-story concept.
  • Experimental model comparisons have not established a production-quality replacement for the reference model.

What I learned

Tests showed that more natural model responses could introduce facts that were not in the source material. That changed how I approach evaluation: a fluent answer is not enough, and test results need to capture missing or unsupported details.
